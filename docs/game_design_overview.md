# 《问道长生》整体设计草案

> 本文档为高层概览，详细系统设计请见 [docs/gdd/README.md](./gdd/README.md)。

## 1. 设计定位与核心体验

**一句话目标**：让玩家在东方修仙世界中，体验「从凡人到渡劫飞升」的完整生命周期，并在宗门、城池、洞府、人际关系之间做出有分量的选择。

**核心情绪曲线**：
- 早期：生存与探索——资源匮乏、奇遇惊喜、拜师入门。
- 中期：经营与抉择——选择流派与城池立场，建立洞府与势力。
- 后期：博弈与超脱——参与宗门战争、城主竞选、世界事件，最终飞升或堕魔。

**设计原则**：
1. **选择有代价**：每次大决定（流派、宗门、城主支持、道侣）都应关闭部分门，打开另一些门。
2. **配置驱动**：数值、事件、对话、地图尽量 JSON 化，方便后续填充与平衡。
3. **模块化扩展**：新系统通过 Manager + Dialog + Config 三件套接入，保持 Engine 薄而稳定。
4. **可视化反馈**：修炼、突破、战争、经营等核心行为都需要明确的 UI/动画/年表记录。

## 2. 核心循环

```
                ┌─────────────┐
                │   探索世界   │
                │ 秘境/遗迹/BOSS │
                └──────┬──────┘
                       ▼
┌──────────┐    ┌─────────────┐    ┌──────────┐
│ 经营洞府  │◄───│  修炼突破   │───►│ 社交关系  │
│药园/阵法/ │    │ 境界/心法/  │    │宗门/道侣/ │
│灵兽/器灵  │    │ 流派/神通   │    │师徒/仇敌  │
└────┬─────┘    └──────┬──────┘    └────┬─────┘
     │                 ▼                │
     │          ┌─────────────┐         │
     └─────────►│ 城池与宗门  │◄────────┘
                │ 任务/交易/战争/政治 │
                └─────────────┘
```

**月度推进节奏**：
- 玩家每月选择一次「主行动」：修炼、探索、闭关、社交、经营。
- 每次月度推进触发：事件判定、洞府/宗门/城池 tick、天气/世界事件结算。
- 重要节点（突破、战争、竞选）进入独立弹窗/战斗/剧情流程。

## 3. 系统架构（现状 + 补齐方向）

| 层级 | 现状 | 建议补齐 |
|------|------|----------|
| **世界层** | `World` + 地点配置 + 传送阵 | 世界地图可视化、区域灵气浓度动态变化 |
| **修炼层** | 境界、灵根、流派、心法、神通 | 渡劫心魔分支、悟道树、法则融合 |
| **战斗层** | 回合制 + 五行克制 + 控制效果 | 战斗镜头/特效、联手技、阵法站位 |
| **经营层** | 洞府租赁、闭关、摆摊、拍卖 | 洞府升级经营、店铺收购、宗门产业 |
| **社交层** | NPC 好感、道侣、师徒、宗门 | NPC 日常作息、恩怨链、势力阵营 |
| **政治层** | 城主竞选、城池政策 | 宗门外交、城池战争、阵营大战 |
| **事件层** | 随机事件、世界事件、妖兽攻城 | 连锁事件、历史年表可视化 |

## 4. 四大成长支柱

### 4.1 修为成长（个人实力）
- **境界**：炼气 → 筑基 → 金丹 → 元婴 → 化神 → 渡劫。
- **灵根**：五行纯度决定属性伤害；变异/融合根解锁特殊神通。
- **流派**：法修/体修/剑修/丹修/器修/魂修/阵修/符修/御兽修/邪修。
- **心法与神通**：通过历练、秘境、论道获取，构建 Build。

### 4.2 洞府经营（私人领地）
- **租赁洞府**：城中洞府提供修炼加成与闭关场所（已实现）。
- **私人洞府**：高境界后可在野外占据灵脉，拥有永久领地。
- **洞府设施**：药园、炼丹室、炼器台、灵兽园、聚灵阵、护山大阵。
- **设施升级**：消耗材料与灵石，升级后提高产出与防御。

### 4.3 势力网络（社会关系）
- **宗门**：外门 → 内门 → 核心 → 长老 → 掌门，参与宗门任务/大比/战争。
- **城池**：通过任务与声望建立关系，竞选城主颁布政策。
- **NPC 关系**：好感、恩怨、师徒、道侣、结拜、仇敌，形成动态社交网络。
- **阵营**：正道 / 魔道倾向影响可加入势力与剧情分支。

### 4.4 资源经济（物质基础）
- **收入来源**：任务奖励、摆摊、拍卖、洞府产出、宗门俸禄、劫掠/护送。
- **消耗出口**：租金、突破丹药、装备强化、设施升级、社交送礼、传送。
- **市场动态**：城池政策、世界事件、天气影响物价，形成套利空间。

## 5. 城池作为核心枢纽

将每座城池设计为「月度决策中枢」，而非单纯的商店集合：

| 建筑 | 核心功能 | 决策点 |
|------|----------|--------|
| 城主府 | 竞选、政策、城池任务 | 支持哪位候选人？颁布什么政策？ |
| 客栈 | 休息、打听消息、触发奇遇 | 花多少钱买情报？相信哪条传闻？ |
| 坊市 | 交易、摆摊、拍卖 | 低买高卖、囤积物资 |
| 演武场 | 擂台挑战、排名 | 挑战谁？连胜风险？ |
| 炼丹阁 | 购买/炼制丹药 | 自采材料还是直接购买？ |
| 洞府 | 租赁、闭关 | 短期冲刺还是长期持有？ |
| 宗门办事处 | 接取宗门任务、外交 | 为宗门效力还是谋取私利？ |

**城池氛围差异**：
- 玄水城：水系资源便宜、水属性修炼加成、夜间妖兽事件。
- 赤焰城：火系/丹修友好、地火洞府、火山喷发随机事件。
- 万妖城：御兽材料丰富、妖核交易、正道阵营声望下降。
- 云岚城：高端洞府、论道/拍卖活跃、租金昂贵。

## 6. 洞府系统扩展设计

在现有租赁/闭关基础上，向「私人领地经营」演进：

### 6.1 洞府类型
- **城中洞府**：租金制、安全、加成固定（已实现）。
- **野外洞府**：占领制、需护山大阵、可升级、可被妖兽/敌对势力攻击。
- **宗门洞府**：宗门职位奖励、共享宗门灵脉。

### 6.2 洞府设施
```json
{
  "facilities": [
    {"id": "spirit_field", "name": "灵田", "produce": ["spirit_herb"], "upkeep": 50},
    {"id": "alchemy_room", "name": "炼丹室", "effect": {"alchemy_success": 0.1}, "upkeep": 80},
    {"id": "beast_park", "name": "灵兽园", "max_beasts": 3, "upkeep": 100},
    {"id": "gathering_array", "name": "聚灵阵", "effect": {"cultivation_speed_bonus": 0.1}, "upkeep": 120}
  ]
}
```

### 6.3 洞府事件
- 灵气潮汐：每月随机提升/降低某种灵气浓度。
- 妖兽袭扰：无护阵时概率触发，胜利得材料，失败设施损坏。
- 访客：NPC 上门求药、论道、挑战、结仇。

## 7. 社交与 NPC 生态

### 7.1 NPC 日程
- 每个 NPC 有固定作息：白天在坊市/宗门，夜晚在客栈/洞府。
- 玩家可在特定地点偶遇，触发对话、任务、战斗。

### 7.2 关系网络
- 关系链：A 是 B 的师父 → 对 A 的好感影响 B 对玩家的态度。
- 恩怨传递：击杀 NPC 可能招致其亲友、宗门、道侣复仇。
- 势力标签：正道/魔道/中立，影响 NPC 对玩家的初始态度。

### 7.3 关键社交玩法
- **论道**：消耗时间与悟性，胜利提升道心、解锁心法/神通。
- **双修**：与道侣共同闭关，双向加成，可能触发情缘事件。
- **收徒**：徒弟定期上缴资源，也可能背叛或引仇上门。

## 8. 世界模拟与事件系统

### 8.1 动态世界层
- **灵气潮汐**：每季度改变各区域灵气浓度，影响修炼速度与秘境产出。
- **势力兴衰**：宗门之间会因资源、恩怨发生战争，玩家可介入。
- **世界 BOSS**：定期刷新，全服/全存档玩家可共同讨伐（单机模式下为 AI 竞争）。

### 8.2 事件分类
| 类型 | 触发方式 | 例子 |
|------|----------|------|
| 随机遭遇 | 探索/移动时 | 路遇劫修、发现遗迹、救助散修 |
| 城池事件 | 月度 tick | 妖兽攻城、商队抵达、城主换届 |
| 宗门事件 | 宗门 tick | 宗门大比、外敌入侵、长老陨落 |
| 世界事件 | 全局 tick | 魔道入侵、天材地宝出世、正道联盟 |
| 个人剧情 | 关系/境界/选择 | 师父召见、道侣危机、仇敌复仇 |

### 8.3 历史年表
- 记录世界大事与玩家抉择，形成「这一世」的独特叙事。
- 可作为结局结算、成就解锁、转世继承的依据。

## 9. 配置与实现规范

### 9.1 配置分层
```
config/
  core/          # 境界、灵根、流派、技能（低频修改）
  world/         # 地点、NPC、宗门、势力（中频）
  events/        # 事件、任务、对话（高频）
  economy/       # 物品、配方、店铺、拍卖（高频）
  ui/            # 标签、颜色、提示文本（纯表现）
```

### 9.2 代码分层
- **Config**：纯数据加载与校验。
- **Manager**：单一系统逻辑，不直接操作 UI。
- **Engine**：组合 Manager，提供游戏 tick 与跨系统接口。
- **UI**：只负责展示与玩家输入，通过 Engine 调用逻辑。
- **Tool**：可视化编辑器、配置校验、资源生成。

### 9.3 新增系统 checklist
1. 设计 JSON schema 并更新 `tools/validate_configs.py`。
2. 实现 `game/xxx_manager.py` 与对应 `tests/test_xxx_manager.py`。
3. 在 `game/engine.py` 中接入，提供 UI 调用接口。
4. 实现 `ui/xxx_dialog.py`（优先复用现有组件）。
5. 在合适地点（城市/主界面）添加入口。
6. 更新 `Player.to_dict/from_dict` 保存新状态。
7. 跑通完整测试套件。

## 11. 关键数值设计建议

- **修炼节奏**：从炼气到筑基约 3~5 年游戏时间，每个大境界提升 2~3 倍实力。
- **经济节奏**：早期灵石紧张，中期通过洞府/经营自给自足，后期可通过城池/战争暴富。
- **死亡/失败**：低境界战斗失败可复活并虚弱；高境界元婴可替死一次；真正死亡触发转世。
- **随机性控制**：奇遇与事件应「可预期地随机」——玩家能通过情报、风水、机缘提高好事件概率。

## 12. 美术与表现建议

- **统一视觉语言**：所有弹窗使用水墨/古风边框、卷轴标题、朱砂印章按钮。
- **状态可视化**：修炼进度、突破光效、阵营值、城池声望都应有进度条或颜色变化。
- **地图沉浸感**：继续完善 2.5D 城市全景图 + 动态粒子（云雾、落叶、萤火）。
- **角色立绘**：按境界/流派/性别生成对应头像，突破大境界时短暂显示光效边框。

---

## 13. 验收标准

- 新玩家能在 10 分钟内理解核心循环。
- 每个大境界都有新的系统解锁，保持新鲜感。
- 任何系统改动后，`tools/validate_configs.py` + `pytest tests/` 全绿。
- 配置占比 ≥ 70%，关键数值调整不需要改代码。
