# 捏脸系统设计方案（双路线：拼装捏脸 + AI 提示词捏脸）

> 状态：待确认（2026-09-05 由秦然起草）
> 目标：让玩家自定义主角外观。两条路线并存、互补，共用同一套数据模型与入口。

---

## 1. 目标与总体思路

| | 路线 A：拼装捏脸（纸娃娃） | 路线 B：AI 提示词捏脸 |
|---|---|---|
| 产出 | 256×256 拼装头像（UI 小头像） | 1024×1024 AI 整张立绘（大立绘） |
| 特点 | 即时预览、参数可复现、风格统一 | 精美独特、成本低、每次结果不同 |
| 依赖 | 部件 PNG 资源集 | Agnes 文生图（已有管线） |
| 实施期 | 第二期 | 第一期 |

**统一原则**：
- 两条路线的入口都是同一个 `FaceCustomizeDialog`（捏脸弹窗），内部用 Tab 切换「拼装捏脸 / AI 立绘」。
- 两条路线的结果**都落到 `player.portrait`（头像文件路径）**，游戏内所有显示头像的地方无感知。
- 捏脸参数全部持久化到存档，可随时回来重调。

## 2. 数据模型与存档

`player` 新增两个字段（`_migrate` 用 setdefault 兼容旧档）：

```json
"face_params": {
  "face": "oval_2", "brow": "sword_1", "eye": "phoenix_2",
  "mouth": "smile_1", "hair": "high_ponytail_3",
  "accessory": "jade_crown", "skin": "fair"
},
"face_traits": {
  "face_shape": "剑眉星目", "eyes": "凤眼微挑",
  "aura": "清冷出尘", "hair_style": "高马尾",
  "outfit": "月白道袍"
}
```

- `face_params`：路线 A 的部件选择（拼装可精确复现）。
- `face_traits`：路线 B 的特征选择（便于"重摇"时保持参数）。

## 3. 路线 B：AI 提示词捏脸（第一期，复用现有管线）

### 3.1 特征表 `config/face_traits.json`

```json
{
  "style_prefix": "A {gender_desc} Chinese fantasy cultivator portrait,",
  "style_suffix": "traditional xianxia robe, soft lighting, ink wash painting style, ethereal atmosphere, detailed face",
  "negative": "low quality, blurry, deformed hands, extra fingers, modern clothes, western style, cartoon, 3d render",
  "dimensions": [
    { "id": "face_shape", "name": "脸型", "options": [
      { "id": "sharp",   "name": "剑眉星目", "prompt": "sharp eyebrows and piercing eyes" },
      { "id": "gentle",  "name": "温润如玉", "prompt": "gentle refined features" } ] },
    { "id": "eyes", "name": "眼神", "options": [ ... ] },
    { "id": "aura", "name": "气质", "options": [ ... ] },
    { "id": "hair_style", "name": "发型", "options": [ ... ] },
    { "id": "outfit", "name": "服饰", "options": [ ... ] }
  ]
}
```

### 3.2 Prompt 拼接规则

```
{style_prefix 性别} + {各维度选中项的 prompt，逗号连接} + {流派/境界 desc} + {style_suffix}
(negative prompt: {negative})
```

流派/境界沿用现有 `build_prompt` 的模板映射，保证与境界体系一致。

### 3.3 UI：FaceCustomizeDialog（AI Tab）

- 左侧：预览头像（复用 PortraitLabel）+「生成立绘」按钮（生成中禁用、显示状态文案）。
- 右侧：5 个维度的下拉选择（默认各选第一项）。
- 生成走现有异步模式（QThreadPool + 信号），失败降级链：AI → 现有默认头像，弹窗提示。
- 生成成功后询问「采用这张？」，采用才写 `player.portrait`（避免白等一分钟却被覆盖）。

## 4. 路线 A：拼装捏脸（第二期）

### 4.1 部件分层（自底向上合成）

```
1 背景色/灵光   2 脸型   3 五官(眉/眼/鼻/嘴)   4 发型   5 饰品(额饰/发簪)
```

- 画布 256×256，显示时缩放（头像 96~128px）。
- 数量规划（首版）：脸型 4 / 眉 4 / 眼 4 / 鼻 3 / 嘴 4 / 发型 6（男女各 6）/ 饰品 4 ≈ 29 个部件。
- 资源目录：`assets/faces/{layer}/{part_id}.png`（透明底 PNG）。

### 4.2 部件资源生成管线（关键难点：风格一致）

1. 用 agnes-image-gen 批量生成，**同一 layer 用同一 prompt 前缀 + 纯白背景**，保证风格接近。
2. 程序化抠图：PIL 色键（接近白色的像素 → 透明）+ 边缘羽化，脚本存 `tools/gen_face_parts.py`。
3. **人工筛选入库**：每部件生成 4 张挑 1 张，不合适的重摇——部件质量决定路线 A 成败。

### 4.3 配置 `config/face_parts.json`

```json
{
  "canvas": 256,
  "layers": [
    { "id": "face", "name": "脸型", "z": 10, "parts": [
      { "id": "oval_1", "name": "鹅蛋脸", "file": "assets/faces/face/oval_1.png" }, ... ] },
    { "id": "brow", "name": "眉", "z": 20, "parts": [ ... ] },
    ...
  ],
  "skins": [ { "id": "fair", "name": "白皙", "tint": null },
             { "id": "wheat", "name": "麦色", "tint": [232, 190, 150] },
             { "id": "bronzed", "name": "古铜", "tint": [205, 160, 120] } ]
}
```

肤色实现：对 `face` 层做 PIL 整体调色（乘 tint），不对五官层染色，避免脏色。

### 4.4 合成器 `game/face_compositor.py`

- `compose(params, out_path)`：按 z 序叠图层 → 肤色调色 → 存 PNG → 返回路径。
- 纯 PIL 实现（不依赖 Qt），**可离线单测**（给定参数断言输出文件存在且尺寸正确）。
- UI 预览实时重合成（部件切换 <50ms，本地合成无延迟）。

### 4.5 UI：FaceCustomizeDialog（拼装 Tab）

- 左侧大预览 + 随机按钮（各层随机挑一件）+ 重置。
- 右侧按层分组的部件选择（图标按钮网格，选中高亮）。
- 「采用此形象」→ 合成 PNG → 写 `player.portrait` + `player.face_params`。

## 5. 与现有系统的兼容

| 现有逻辑 | 兼容策略 |
|---|---|
| 大境界突破自动切换立绘 `find_best_portrait_resource` | 若玩家捏过脸（face_params/face_traits 非空），**不自动替换**，改为弹提示"可去捏脸界面生成高阶立绘"；未捏脸的保持现状 |
| 角色创建流程 | 创建对话框加「捏脸…」按钮（可选步骤，跳过则用默认头像）；路线 B 特征此时即可选 |
| 存档迁移 | `_migrate` setdefault 两个空 dict，旧档零影响 |
| 状态面板 | 加「重新捏脸」入口（复用同一弹窗） |

## 6. 分期实施计划

| 期 | 内容 | 产出 |
|---|---|---|
| **一期（路线 B）** | face_traits.json + FaceCustomizeDialog(AI Tab) + prompt 拼接 + 异步 worker 复用 + 存档字段 + 测试 | 玩家可选特征生成专属立绘 |
| **二期（路线 A）** | tools/gen_face_parts.py（批量生成+抠图）→ 人工筛选部件入库 → face_parts.json + face_compositor.py + 拼装 Tab + 测试 | 玩家可即时拼装头像 |
| **三期（打磨）** | 随机捏脸、多套方案保存切换、突破立绘提示、捏脸历史 | 体验完善 |

一期一次会话可完成；二期工作量主要在部件资源（生成+筛选），合成器与 UI 本身不重。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| AI 生成慢（约 1 分钟）/503 队列满 | 已有重试+降级；生成中状态提示；拼装头像可作即时兜底 |
| AI 部件风格不一致 | 同层统一 prompt 前缀 + 人工筛选；首版部件量从简（29 个），后期扩充 |
| 捏脸后与突破立绘逻辑冲突 | 第 5 节优先级策略：捏过脸则不自动替换 |
| 存档膨胀（多张生成图） | generated_* 图片仍由玩家手动管理；后续可加"清理未引用立绘"工具 |
